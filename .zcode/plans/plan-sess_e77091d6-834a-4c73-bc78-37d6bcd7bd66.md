# Automated Tests for POSSE (node:test, zero deps)

## Goal
Cover the highest-bug-risk POSSE code with automated tests using Node 22's built-in `node:test` runner — no new dependencies. Tests run in CI (build-check workflow) so regressions are caught before merge.

## Runner setup
- Add `"test": "node --test"` to `site/package.json` (auto-discovers `*.test.mjs`).
- Tests co-located as `*.test.mjs` next to each lib file.
- Add a `npm test` step to `build-check.yml` after `npm run check`.

## Test files (8 total)

### Pure-logic tests (no mocking — the bulk)
1. **`scripts/lib/social.test.mjs`** — `normalizeSocial` + `teaserBlurb`
   - Canonical URL appended to last post for twitter/bluesky/mastodon, NOT linkedin
   - Array (thread) vs string (single) handling
   - Fallback chain: `social.<platform>` → `socialPost` → `description` → empty
   - `image` flag defaults true, false only when explicit
   - Empty/whitespace filtering

2. **`scripts/lib/markdown.test.mjs`** — `mdxToMarkdown`
   - ESM imports stripped
   - JSX component tags stripped (replaced with empty paragraph)
   - Component with image → `![](url)` inlined in place
   - Component without image → stripped, interactive note still appended
   - Code fences + `$$math$$` preserved
   - Interactive note appears iff imports or capitalized JSX present

3. **`src/lib/tags.test.mjs`** — `tagStyle` + `allTags` (TypeScript via Node's TS support)
   - Known tag → correct color family classes
   - Unknown tag → zinc fallback
   - Case-insensitive lookup
   - `allTags` tallies counts, sorts by count desc then name

4. **`src/lib/readingTime.test.mjs`** — `readingTime`
   - Strips code/links/images before counting
   - Returns ≥1 even for tiny bodies
   - ~200 wpm math

5. **`scripts/lib/component-shot.test.mjs`** — `componentsInBody` (only the pure function; skip the Playwright part)
   - Detects `<BinPacker ... />`, `<Chart>` style tags
   - Returns unique names (dedupes)
   - Requires ≥2 char capitalized names (per the regex) — pin this edge case
   - Ignores lowercase html tags

### Adapter available() + dry-run tests (no mocking — short-circuits before HTTP)
6. **`scripts/lib/platforms/adapters.test.mjs`** — covers all 7 adapters
   - `available()` reflects env vars (set/unset per test)
   - `publish({dryRun: true})` returns `{id: 'dry-run', ...}` for each API adapter without calling fetch
   - Medium/Substack `publish()` returns `{id: 'manual'}` (manual-package needs fs mock — test via temp dir)

### Frontmatter surgical-edit (the highest-risk regex logic — fs via temp dir)
7. **`scripts/lib/frontmatter.test.mjs`** — `writeSyndicationIds`
   - Uses a real temp dir (`fs.mkdtemp`) — no mocking, tests the actual fs round-trip
   - Inserts a new `syndication:` block into frontmatter with no existing block
   - Updates an existing block in place (no duplication)
   - Preserves the author's original formatting (quotes, dates, array style) — only the syndication block changes
   - Idempotent: re-running with the same IDs returns `false` (no write)
   - Number vs string IDs treated as equal (idempotent across types)
   - Body preserved byte-for-byte

8. **`scripts/lib/manual-package.test.mjs`** — `seedPackage` + `addPlatformNote` (temp dir)
   - `seedPackage` writes the header (title, canonical, tags, body, "How to publish" section)
   - Idempotent: second `seedPackage` call doesn't overwrite
   - `addPlatformNote` appends per-platform instructions
   - Both Medium + Substack contributing to one file composes cleanly

## TypeScript handling
- `src/lib/tags.ts` and `readingTime.ts` run via Node 22's built-in TS support (`--experimental-strip-types` is on by default in Node 22.6+ for type-only syntax).
- `tags.ts` has a type-only `import type { CollectionEntry }` from `astro:content` — strip-types drops it. Tests pass plain `{data: {tags: [...]}}` objects.
- Skip `path.ts` (needs `import.meta.env` which doesn't exist outside Vite — covered by `astro check` + build instead).

## CI integration
Add to `build-check.yml` after the existing `check` + `build` steps:
```yaml
- name: Test
  working-directory: ./site
  run: npm test
```

## What's NOT tested (deliberate)
- `og-image.mjs`, `screenshotComponent` — heavy native deps (satori, sharp, Playwright); covered by the existing dry-run integration
- Live `publish()` HTTP calls (fetch mocking for 5 adapters) — deferred to keep this PR focused; the dry-run paths + available() cover the logic, and the real HTTP is exercised by actual syndicate runs
- `path.ts` — Vite-specific `import.meta.env`
